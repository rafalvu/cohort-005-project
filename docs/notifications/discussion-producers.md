# Discussion Notification producers (#14)

Question and reply source changes and required recipient Notifications share one synchronous SQLite transaction. Both the lesson discussion action and Instructor unanswered-queue action use it. Authentication, request-country access checks and request parsing finish before the transaction; no network work runs inside it.

The feature remains inactive by default. `CADENCE_NOTIFICATIONS_ENABLED=true` enables producer persistence for isolated verification only. Do not set it in normal development/demo or production until the complete feature has passed the parent issue #11 activation gate. No navigation or Notification read API is enabled by this slice. Tests explicitly enable the flag and verify disabled behavior. Future producers must use this same activation gate.

Both browser forms keep a UUID operation identity through an in-flight submission and replace it only after acknowledged success. IDs initialize after client mount to avoid server/client hydration mismatches; posting is disabled until initialized. The server scopes each operation to the actor, checks a persisted fingerprint of lesson, parent and original body, and returns the existing result for a retry. Reusing an identity for different content fails. Identities remain after soft deletion or editing. Distinct form submissions have distinct IDs. Hard deletion and future lifecycle work must preserve the source replay guarantee.

Migration 0013 adds nullable identity/fingerprint columns and a unique actor/operation index. Historical and seed comments keep null identities; there is no backfill. Apply migrations to existing databases without reseeding. The seed script was exercised only against a fresh isolated temporary database.

Recipient eligibility uses each recipient's Enrollment, course ownership and Platform Admin role. Country-dependent restrictions belong to the recipient's later read request, never the actor's country. Reading and lifecycle enforcement remain subsequent slices. Previous repliers include authors of soft-deleted replies, consistent with the contract's “all previous repliers”; replying to a deleted question preserves existing posting behavior but creates no Notification.

Route integration tests use real session cookies, real migrations and real SQLite. They cover multiple admins, overlapping roles, participant/access differences, both reply routes, replay and concurrent action invocation, distinct events, invalid/unauthorized actions, edits/deletions, restored unanswered queues, and persistence failure after an earlier recipient insert. SQLite trigger failures verify source and recipient rollback together. Concurrent requests are serialized by the application's synchronous single-owner SQLite transaction, matching ADR 0006.
